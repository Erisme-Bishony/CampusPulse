# 管理员后台分工与接口说明

更新时间：2026-10-27

## 1. 结论

**管理员界面由 B 写，A 不需要写管理员页面，也不需要为管理员单独做 Android 界面。**

管理后台是运行在电脑浏览器里的 Thymeleaf 服务端页面，和 Android 客户端是两条独立的入口：

```text
Android（A 负责） ── Retrofit/HTTP ──> /api/v1/**  ──> MySQL
浏览器（B 负责）  ── Session + HTML ──> /admin/**    ──> MySQL
```

管理员在后台发布、修改活动后，Android 端通过现有的 `GET /api/v1/activities` 就能看到，A 不需要新增接口或页面。

## 2. 为什么由 B 写

- 分工方案里 B 是服务端主负责人，管理后台属于服务端的一部分。
- 管理后台需要直接操作 `admin`、`activity`、`tag`、`user`、`registration`、`behavior` 等表，和 B 维护的数据库、实体、事务边界在一起，放在 B 侧改动最小。
- A 的时间应该留给 Android 首页、详情、登录态、报名、推荐展示和答辩演示；管理员页面不是 Android 功能。

如果 A 想参与，可以让 A 帮忙点测后台页面或提改进意见，但不把后台页面作为 A 的交付物。

## 3. 访问方式

| 项 | 约定 |
|---|---|
| 登录页 | `GET /admin/login` |
| 登录提交 | `POST /admin/login`，表单字段 `username`、`password` |
| 退出 | `POST /admin/logout` |
| 登录态 | `HttpSession`，默认 30 分钟；不使用学生 JWT |
| 权限 | 仅 `admin` 表账号；学生 token 不能访问 `/admin/**` |
| CSRF | 后台表单带 CSRF token；B 在模板里统一放隐藏字段 |
| 测试账号 | `admin / admin123` |

后台是浏览器页面，不返回 Android 使用的 `{code,message,data,timestamp}` JSON。管理员登录成功后是 302 跳转到 `/admin`，不是返回 token。

## 4. 页面与动作清单（B 实现）

> 当前状态：**未实现**，以下为 B 的实现清单，不是已经可用的接口。B 完成后会把状态改成“已实现”，并在群里通知 A 可以演示“后台发布 → App 可见”。

### 4.1 登录与仪表盘

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/login` | 登录页 |
| POST | `/admin/login` | 校验管理员账号，成功进 `/admin` |
| POST | `/admin/logout` | 清 Session |
| GET | `/admin` | 仪表盘：用户数、活动数、报名数、今日新增报名、即将开始活动 |

### 4.2 活动管理

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/activities` | 活动列表，支持按状态/关键词筛选 |
| GET | `/admin/activities/new` | 新建表单 |
| POST | `/admin/activities` | 创建活动 |
| GET | `/admin/activities/{id}/edit` | 编辑表单 |
| POST | `/admin/activities/{id}` | 保存修改 |
| POST | `/admin/activities/{id}/cancel` | 下架活动（状态改 `CANCELLED`，保留报名历史） |

活动表单字段与 `activity` 表一致：

- `title`：必填，≤120 字
- `description`：必填
- `location`：必填，≤120 字
- `type`：必填，中文类型（讲座/比赛/招新/演出/志愿/沙龙/宣讲/工作坊/市集）
- `startTime`、`endTime`、`signupDeadline`：必填，`yyyy-MM-dd'T'HH:mm` 表单时间
- `capacity`：必填，正整数
- `coverUrl`、`organizer`：可空
- `status`：`DRAFT` / `PUBLISHED` / `CANCELLED`
- `tagIds`：可多选，至少一个

校验规则：

- `endTime` 必须晚于 `startTime`。
- `signupDeadline` 不能晚于 `startTime`。
- 编辑时 `capacity` 不能小于当前 `signupCount`。
- 创建时 `signupCount` 固定为 0，`viewCount`、`shareCount` 固定为 0。

### 4.3 标签管理

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/tags` | 标签列表 |
| POST | `/admin/tags` | 新增标签：`name`、`color`、`sortOrder` |
| POST | `/admin/tags/{id}/delete` | 删除标签；仍被活动或用户引用时拒绝，并提示引用数 |

### 4.4 用户管理

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/users` | 用户列表（用户名、邮箱、手机、状态、注册时间） |
| POST | `/admin/users/{id}/status` | 启用/禁用；不做物理删除 |

### 4.5 统计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/statistics` | 4 个数字卡片 + 活动报名表：活动数、用户数、报名数、浏览/分享数；按活动汇总报名和浏览 |

统计只读，不单独提供 JSON API；如果以后要做“管理员 Android 端”，再另开 `/api/v1/admin/**`，不属于本次课程范围。

## 5. 与 A 的边界

- A 继续用现有 `/api/v1/**`，不需要实现 `/admin/**`。
- B 完成后台后，A 只需确认：后台发布的新活动能在 App 列表/详情出现。
- 管理员账号只用于浏览器后台，不写进 Android 登录页，也不做成学生可登录的角色。
- 如果后台改动导致活动字段变化，B 先更新 `docs/给A的联调同步.md` 和 `docs/openapi.json`，再通知 A。

## 6. 交付顺序

1. 后台登录 + Session 拦截 + 仪表盘。
2. 活动列表、新建、编辑、下架。
3. 标签管理、用户列表/启停。
4. 统计页。
5. 用真实 MySQL 走一遍“管理员发布 → Android 列表可见 → 学生报名 → 后台看到报名数”。

# 管理员后台说明

更新时间：2026-10-27

状态：已实现，已通过自动化测试和真实 MySQL 页面验收。

## 1. 结论

**管理员界面由 B 写，A 不需要写管理员页面，也不需要为管理员单独做 Android 界面。**

管理后台是运行在电脑浏览器里的 Thymeleaf 服务端页面，和 Android 客户端是两条独立的入口：

```text
Android（A 负责） ── Retrofit/HTTP ──> /api/v1/**  ──> MySQL
浏览器（B 负责）  ── Session + HTML ──> /admin/**    ──> MySQL
```

管理员在后台发布、修改活动后，Android 端通过现有的 `GET /api/v1/activities` 就能看到，A 不需要新增接口或页面。

## 2. 为什么由 B 写

- 分工方案里 B 是服务端主负责人，管理后台属于服务端的一部分。
- 管理后台需要直接操作 `admin`、`activity`、`tag`、`user`、`registration`、`behavior` 等表，和 B 维护的数据库、实体、事务边界在一起，放在 B 侧改动最小。
- A 的时间应该留给 Android 首页、详情、登录态、报名、推荐展示和答辩演示；管理员页面不是 Android 功能。

如果 A 想参与，可以让 A 帮忙点测后台页面或提改进意见，但不把后台页面作为 A 的交付物。

## 3. 访问方式

| 项 | 约定 |
|---|---|
| 登录页 | `GET /admin/login` |
| 登录提交 | `POST /admin/login`，表单字段 `username`、`password` |
| 退出 | `POST /admin/logout` |
| 登录态 | `HttpSession`，默认 30 分钟；不使用学生 JWT |
| 权限 | 仅 `admin` 表账号；学生 token 不能访问 `/admin/**` |
| 测试账号 | `admin / admin123` |

后台是浏览器页面，不返回 Android 使用的 `{code,message,data,timestamp}` JSON。管理员登录成功后是 302 跳转到 `/admin`，不是返回 token。

本地启动服务后访问：

```text
http://127.0.0.1:8081/admin/login
```

## 4. 页面与动作（已实现）

### 4.1 登录与仪表盘

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/login` | 登录页 |
| POST | `/admin/login` | 校验管理员账号，成功进 `/admin`，失败回登录页并提示 |
| POST | `/admin/logout` | 清 Session，回登录页 |
| GET | `/admin` | 仪表盘：用户数、今日新增用户、活动数、已发布活动、即将开始、报名数、有效报名、今日报名、行为数、今日行为；最近活动和即将开始活动各 5 条 |

### 4.2 活动管理

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/activities` | 活动列表，按创建时间倒序；显示状态、报名数/容量、开始时间 |
| GET | `/admin/activities/new` | 新建表单 |
| POST | `/admin/activities/save` | 创建或保存活动；带 `id` 为编辑 |
| GET | `/admin/activities/{id}/edit` | 编辑表单 |
| POST | `/admin/activities/{id}/toggle` | 在 `DRAFT` 与 `PUBLISHED` 之间切换；已结束活动拒绝下架/发布 |

活动表单字段：

- `title`：必填，≤120 字
- `description`：必填
- `location`：必填，≤120 字
- `type`：必填，中文类型：讲座、比赛、文艺、志愿、体育、社团、其他
- `startTime`、`endTime`、`signupDeadline`：必填，`yyyy-MM-dd'T'HH:mm` 表单时间
- `capacity`：必填，正整数
- `coverUrl`、`organizer`：可空
- `status`：`DRAFT` / `PUBLISHED`
- `tagIds`：可多选，可为空

校验规则：

- `endTime` 必须晚于 `startTime`。
- `signupDeadline` 不能晚于 `startTime`。
- 编辑时 `capacity` 不能小于当前 `signupCount`。
- 创建时 `signupCount`、`viewCount`、`shareCount` 固定为 0。
- 新建默认 `PUBLISHED`；草稿不会出现在 Android 活动列表。

后台没有物理删除活动，避免误删报名记录；需要下架时把状态改为 `DRAFT`。

### 4.3 标签管理

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/tags` | 标签列表，显示引用数和排序 |
| POST | `/admin/tags/create` | 新增标签：`name`、`color`、`sortOrder` |
| POST | `/admin/tags/{id}/delete` | 删除标签；仍被活动或用户引用时拒绝并提示 |

### 4.4 用户管理

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/users` | 用户列表：用户名、邮箱、手机、角色、状态、注册时间、兴趣标签 |

当前用户页是只读列表，不做物理删除，也没有启用/禁用按钮；如后续需要，再补 `POST /admin/users/{id}/status`。

## 5. CSRF 与权限边界

- 后台业务表单（活动保存、上下架、标签新增/删除、退出）都带隐藏字段 `_csrf`，无 token 的 POST 返回 403。
- 登录入口 `POST /admin/login` 在建立会话之前，当前不校验 CSRF；登录后的管理动作全部校验。
- 学生 JWT 只对 `/api/v1/**` 生效，不能访问 `/admin/**`；管理员 Session 也不能调用需要学生身份的业务接口。

## 6. 与 A 的边界

- A 继续用现有 `/api/v1/**`，不需要实现 `/admin/**`。
- B 完成后台后，A 只需确认：后台发布的新活动能在 App 列表/详情出现。
- 管理员账号只用于浏览器后台，不写进 Android 登录页，也不做成学生可登录的角色。
- 如果后台改动导致活动字段变化，B 先更新 `docs/给A的联调同步.md` 和 `docs/openapi.json`，再通知 A。
